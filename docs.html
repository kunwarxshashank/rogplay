Rogplay Addon API

Complete documentation for the Rogplay plugin-based content addon system. Addons extend streaming capabilities by providing external catalogs, search, and metadata.

Overview

Rogplay's addon system is a plugin-based content source framework. Users install addons via JSON manifest URLs that describe catalogs, search endpoints, and metadata sources. The system supports multiple formats including a native Rogplay format, the standard Stremio manifest format, and specialized types for music, subtitles, and live TV.

Addons are managed client-side via a Zustand store (addonsStore.ts), persisted to MMKV (mobile) or localStorage (web), and optionally synced to a backend for cross-device use by premium users.

Built-in addons: Two addons ship pre-installed — TMDB Addon (cinema catalog) and OpenSubtitle Addon (subtitles). These are always prepended and cannot be removed.

Addon Types

Each addon is classified into a type at runtime based on its manifest content and URL. The type determines how the addon is rendered, what UI it integrates with, and how its catalogs are fetched.

Type Detection & Mapping

The store's addAddon() and loadAddons() functions use the following detection priority:

1. Music check        ← addontype === "music" OR name/title contains "music"
2. Stremio check      ← URL ends in "manifest.json" OR (has id + resources + catalogs)
   → subtype derived from manifest.types:
      - includes "tv"/"channel" → livetv
      - includes "movie"        → movie
      - includes "series"       → series
      - otherwise               → stremio
3. TMDB/Server check  ← addontype === "tmdbaddon" OR "serveraddon" → type: cinema
4. Generic fallback   ← Array response or single object

Auto-generated URLs for Stremio Catalogs

URL PatternTemplateExample
Catalog endpoint{baseUrl}/catalog/{type}/{id}.jsonhttps://example.com/catalog/movie/top.json
Pagination{baseUrl}/catalog/{type}/{id}/skip=\${stremioSkip}.json.../skip=20.json

The baseUrl is derived by stripping /manifest.json from the addon's source URL.

API Reference

Add Addon

addAddon(url: string) → Promise<boolean>

Installs a new addon by fetching its manifest JSON from the given URL.

ParameterTypeDescription
urlstringURL of the addon manifest JSON. Auto-prepends https:// if missing. Handles %2F → / decoding.
ResultDescription
trueAddon fetched and added successfully
throws Error"Addon already exists" if URL is already installed; "Failed to fetch addon: ..." on network/manifest errors

Flow:

1. Normalize URL (add https:// if needed, decode %2F)
2. Check for duplicates in addonUrls[]
3. GET url (8 second timeout)
4. Parse JSON and detect addon type (music → Stremio → tmdbaddon/serveraddon → generic)
5. Create Addon object with source = url
6. Append to addons[] and addonUrls[]
7. Persist to local storage (MMKV / localStorage)
8. Sync with backend (if premium user)
9. Return true

Remove Addon

removeAddon(sourceUrl: string) → Promise<void>

Removes an installed addon by its source URL. Built-in addons cannot be removed.

ParameterTypeDescription
sourceUrlstringThe source field value (the original manifest URL)

Protected sources: TMDB_BUILTIN_SOURCE and OPENSUBTITLE_SOURCE are silently ignored.

Load Addons

loadAddons(incomingUrls?: string[]) → Promise<void>

Initializes the addon store. Called on app mount. Handles caching, network refresh, and backend sync.

ParameterTypeDefaultDescription
incomingUrlsstring[] | undefined—Optional URLs from deep link or external source. When provided, they replace stored URLs and trigger a backend sync.

Flow:

1. Restore active cinema addon from storage
2. Determine URL list:
   a. incomingUrls provided → use them
   b. Premium user → fetch from backend GET /get-addons/:email
   c. Non-premium → load from local storage
3. Deduplicate and filter empty URLs
4. Load cached addon data from storage for instant display
5. Fetch fresh manifests from network (concurrency: 4):
   - Success → parse manifest, detect type, create Addon objects
   - Failure → fall back to cached data for that URL
6. Prepend built-in addons (TMDB + OpenSubtitle)
7. Auto-select TMDB as active cinema addon if none set
8. Update store state, cache fresh data
9. If incomingUrls provided, sync with backend

React hook that resolves the active addon's full configuration:

{
  addon: Addon,                    // The active addon object
  settings: {
    showfilter: boolean,           // Show filter button (default: false)
    showottsection: boolean,       // Show OTT platform section (default: false)
    showslider: boolean            // Show hero slider (default: false)
  },
  catalogs: Catalog[],             // Mapped catalogs with URLs + pagination
  searchcatalog: SearchCatalog[],  // Search catalogs (Rogplay + Stremio combined)
  slidercatalog: object | null,    // Hero slider config
  addontype: string,               // "tmdbaddon" | "serveraddon" | "stremio" | "music"
  addonUrl: string,                // The manifest URL
  addonManifest: string,           // JSON-stringified manifest
  idPrefixes: string[]             // e.g. ["tmdb", "tt"]
}

Stremio catalog transformation: For Stremio-like addons (addontype === "stremio" || "music"), if a catalog has no url, the hook auto-generates catalog, pagination, and search URLs from the manifest.

Fetch Catalog

fetchAddonCatalog(catalogUrl: string, page?: number, addonType?: string, addonMeta?: { url, manifestStr }) → Promise<Item[]>

Fetches and normalizes items from an addon catalog URL.

ParameterTypeDefaultDescription
catalogUrlstring—Catalog URL with optional ${page} or ${stremioSkip} placeholders
pagenumber1Page number for pagination
addonTypestring"serveraddon"Determines how to parse response: "stremio"/"music" → data.metas || data.results || data.items; "tmdbaddon" → data.results; other → fallback chain
addonMetaobjectundefined{ url: string, manifestStr: string } attached to each result item

Response normalization: Each item is mapped to:

{
  id: string,                     // Encoded ID (from id/_id/tmdbId/url/logo/title or generated hash)
  title: string,                  // title || name || label || heading
  poster_path: string,            // poster_path || poster || logo || background || image || thumbnail || thumb
  media_type: "tv" | "movie",     // Derived from type/kind fields
  addonType: string,              // The addonType parameter
  _addonUrl: string,              // The catalog URL or addonMeta.url
  _addonManifestStr: string,      // addonMeta.manifestStr
  ...originalItem                 // All original fields preserved
}

Error resilience: If the response is not valid JSON, the function attempts to extract JSON from the raw text by finding the first [ or { and trimming to the last matching bracket.

Data Model

Addon Interface (Runtime)

The normalized addon object used throughout the app:

interface Addon {
  title: string;          // Display name
  description: string;    // Short description
  logo: string;           // Logo URL
  url: string;            // Manifest URL / content URL
  type: string;           // Runtime type: cinema | stremio | music | livetv | movie | series | subtitles
  source: string;         // The URL from which this addon was fetched (unique key)

  // Optional runtime fields:
  id?: string;            // Unique ID (e.g. "tmdb-builtin", "opensubtitle-builtin")
  addontype?: string;     // Raw manifest addontype: tmdbaddon | serveraddon | music
  isBuiltin?: boolean;    // true for pre-installed addons
  manifest?: object;      // Full raw manifest JSON

  [key: string]: any;     // All original manifest fields preserved
}
